Build a dbt Layer with Cortex Code

~20 min

Use Cortex Code — Snowflake's built-in AI coding assistant — to scaffold and deploy a dbt transformation layer directly from the Snowsight UI. No terminal required. Cortex Code will generate your staging and mart models, configure the project, and run the deployment.

💬
What is Cortex Code?

Cortex Code is an AI-powered coding assistant built into Snowflake. It understands your data schema, writes SQL and dbt models, and can deploy them — all within the Snowflake platform. Think of it as your pair programmer that already knows your data.

3.2 — Prompt Cortex Code to scaffold the dbt project

Copy and paste this prompt into the Cortex Code chat:

Cortex Code Prompt 
Create a dbt project called barclays_payments that builds 3 models in BARCLAYS_HOL.ANALYTICS schema. Use BARCLAYS_WH warehouse. Here is the EXACT specification:

MODEL 1: stg_payments (materialized as table)
Source: BARCLAYS_HOL.RAW_DATA.PAYMENTS
Output columns (use these EXACT names):
  - PAYMENT_ID (VARCHAR, from PAYMENT_ID)
  - PAYMENT_DATE (TIMESTAMP, from PAYMENT_DATE)
  - PAYMENT_TYPE (VARCHAR, UPPER(PAYMENT_TYPE))
  - CHANNEL (VARCHAR, UPPER(CHANNEL))
  - CURRENCY (VARCHAR)
  - AMOUNT (NUMBER(15,2), cast from AMOUNT)
  - STATUS (VARCHAR, UPPER(STATUS))
  - PROCESSING_TIME_MS (NUMBER, from PROCESSING_TIME_MS)
  - REGION (VARCHAR, UPPER(REGION))
  - IS_SUCCESSFUL (BOOLEAN, = TRUE when STATUS = 'COMPLETED')
  - IS_FAILED (BOOLEAN, = TRUE when STATUS = 'FAILED')

MODEL 2: mart_payment_kpis (materialized as table)
Source: ref('stg_payments')
Group by: DATE_TRUNC('DAY', PAYMENT_DATE) AS PAYMENT_DATE, PAYMENT_TYPE, REGION
Output columns (use these EXACT names):
  - PAYMENT_DATE
  - PAYMENT_TYPE
  - REGION
  - TOTAL_PAYMENTS (COUNT(*))
  - TOTAL_VOLUME (SUM(AMOUNT))
  - SUCCESS_RATE_PCT (ROUND(COUNT_IF(IS_SUCCESSFUL)::FLOAT / COUNT(*) * 100, 2))
  - AVG_PROCESSING_TIME_MS (ROUND(AVG(PROCESSING_TIME_MS), 0))
  - P95_PROCESSING_TIME_MS (ROUND(PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY PROCESSING_TIME_MS), 0))

MODEL 3: mart_sla_compliance (materialized as table)
Source: ref('mart_payment_kpis') JOIN BARCLAYS_HOL.RAW_DATA.SLA_DEFINITIONS ON PAYMENT_TYPE = PAYMENT_TYPE
Output columns (use these EXACT names):
  - PAYMENT_DATE (from mart_payment_kpis)
  - PAYMENT_TYPE (from mart_payment_kpis)
  - REGION (from mart_payment_kpis)
  - SUCCESS_RATE_PCT (from mart_payment_kpis)
  - P95_PROCESSING_TIME_MS (from mart_payment_kpis)
  - SLA_TARGET_SUCCESS_RATE (from SLA_DEFINITIONS.TARGET_SUCCESS_RATE)
  - MAX_PROCESSING_TIME_MS (from SLA_DEFINITIONS.MAX_PROCESSING_TIME_MS)
  - SLA_STATUS (CASE:
      'COMPLIANT' when SUCCESS_RATE_PCT >= SLA_TARGET_SUCCESS_RATE AND P95_PROCESSING_TIME_MS <= MAX_PROCESSING_TIME_MS,
      'AT RISK' when SUCCESS_RATE_PCT >= SLA_TARGET_SUCCESS_RATE * 0.95,
      else 'BREACH')

Configuration:
- dbt_project.yml with project name barclays_payments
- profiles.yml targeting snowflake, database BARCLAYS_HOL, warehouse BARCLAYS_WH
- schema.yml with not_null tests on key columns and accepted_values test on SLA_STATUS ('COMPLIANT', 'AT RISK', 'BREACH')

After generating all files, run dbt run and dbt test.

3.3 — Validate the dbt output matches the specification

Once Cortex Code finishes, run this validation script in a Snowsight worksheet. Every check should return PASS:

SQL 
-- =====================================================
-- STEP 3 VALIDATION: Verify dbt output matches spec
-- =====================================================

USE DATABASE BARCLAYS_HOL;

-- 1. Check all 3 tables exist in ANALYTICS
WITH expected_tables AS (
    SELECT column1 AS TABLE_NAME FROM VALUES
        ('STG_PAYMENTS'),
        ('MART_PAYMENT_KPIS'),
        ('MART_SLA_COMPLIANCE')
),
actual_tables AS (
    SELECT TABLE_NAME
    FROM INFORMATION_SCHEMA.TABLES
    WHERE TABLE_SCHEMA = 'ANALYTICS' AND TABLE_TYPE = 'BASE TABLE'
)
SELECT
    e.TABLE_NAME,
    IFF(a.TABLE_NAME IS NOT NULL, 'PASS', 'FAIL - TABLE MISSING') AS STATUS
FROM expected_tables e
LEFT JOIN actual_tables a ON e.TABLE_NAME = a.TABLE_NAME;

-- 2. Check all expected columns exist per table
WITH expected_columns AS (
    SELECT column1 AS TABLE_NAME, column2 AS COLUMN_NAME FROM VALUES
        -- stg_payments
        ('STG_PAYMENTS', 'PAYMENT_ID'),
        ('STG_PAYMENTS', 'PAYMENT_DATE'),
        ('STG_PAYMENTS', 'PAYMENT_TYPE'),
        ('STG_PAYMENTS', 'CHANNEL'),
        ('STG_PAYMENTS', 'CURRENCY'),
        ('STG_PAYMENTS', 'AMOUNT'),
        ('STG_PAYMENTS', 'STATUS'),
        ('STG_PAYMENTS', 'PROCESSING_TIME_MS'),
        ('STG_PAYMENTS', 'REGION'),
        ('STG_PAYMENTS', 'IS_SUCCESSFUL'),
        ('STG_PAYMENTS', 'IS_FAILED'),
        -- mart_payment_kpis
        ('MART_PAYMENT_KPIS', 'PAYMENT_DATE'),
        ('MART_PAYMENT_KPIS', 'PAYMENT_TYPE'),
        ('MART_PAYMENT_KPIS', 'REGION'),
        ('MART_PAYMENT_KPIS', 'TOTAL_PAYMENTS'),
        ('MART_PAYMENT_KPIS', 'TOTAL_VOLUME'),
        ('MART_PAYMENT_KPIS', 'SUCCESS_RATE_PCT'),
        ('MART_PAYMENT_KPIS', 'AVG_PROCESSING_TIME_MS'),
        ('MART_PAYMENT_KPIS', 'P95_PROCESSING_TIME_MS'),
        -- mart_sla_compliance
        ('MART_SLA_COMPLIANCE', 'PAYMENT_DATE'),
        ('MART_SLA_COMPLIANCE', 'PAYMENT_TYPE'),
        ('MART_SLA_COMPLIANCE', 'REGION'),
        ('MART_SLA_COMPLIANCE', 'SLA_TARGET_SUCCESS_RATE'),
        ('MART_SLA_COMPLIANCE', 'SUCCESS_RATE_PCT'),
        ('MART_SLA_COMPLIANCE', 'P95_PROCESSING_TIME_MS'),
        ('MART_SLA_COMPLIANCE', 'MAX_PROCESSING_TIME_MS'),
        ('MART_SLA_COMPLIANCE', 'SLA_STATUS')
),
actual_columns AS (
    SELECT TABLE_NAME, COLUMN_NAME
    FROM INFORMATION_SCHEMA.COLUMNS
    WHERE TABLE_SCHEMA = 'ANALYTICS'
)
SELECT
    e.TABLE_NAME,
    e.COLUMN_NAME,
    IFF(a.COLUMN_NAME IS NOT NULL, 'PASS', 'FAIL - COLUMN MISSING') AS STATUS
FROM expected_columns e
LEFT JOIN actual_columns a ON e.TABLE_NAME = a.TABLE_NAME AND e.COLUMN_NAME = a.COLUMN_NAME
ORDER BY e.TABLE_NAME, e.COLUMN_NAME;

-- 3. Check data integrity (rows exist and values are sensible)
SELECT
    'STG_PAYMENTS' AS TABLE_NAME,
    COUNT(*) AS ROW_COUNT,
    IFF(COUNT(*) >= 50000, 'PASS', 'FAIL - ROW COUNT LOW') AS STATUS
FROM ANALYTICS.STG_PAYMENTS
UNION ALL
SELECT
    'MART_PAYMENT_KPIS',
    COUNT(*),
    IFF(COUNT(*) > 100, 'PASS', 'FAIL - ROW COUNT LOW')
FROM ANALYTICS.MART_PAYMENT_KPIS
UNION ALL
SELECT
    'MART_SLA_COMPLIANCE',
    COUNT(*),
    IFF(COUNT(*) > 10, 'PASS', 'FAIL - ROW COUNT LOW')
FROM ANALYTICS.MART_SLA_COMPLIANCE;

-- 4. Check SLA_STATUS contains only expected values
SELECT
    SLA_STATUS,
    COUNT(*) AS COUNT,
    IFF(SLA_STATUS IN ('COMPLIANT', 'AT RISK', 'BREACH'), 'PASS', 'FAIL - UNEXPECTED VALUE') AS STATUS
FROM ANALYTICS.MART_SLA_COMPLIANCE
GROUP BY SLA_STATUS;

-- 5. Final verdict
SELECT
    IFF(
        (SELECT COUNT(*) FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_SCHEMA='ANALYTICS' AND TABLE_NAME IN ('STG_PAYMENTS','MART_PAYMENT_KPIS','MART_SLA_COMPLIANCE')) = 3
        AND (SELECT COUNT(*) FROM ANALYTICS.MART_SLA_COMPLIANCE WHERE SLA_STATUS IN ('COMPLIANT','AT RISK','BREACH')) > 0
        AND (SELECT COUNT(*) FROM ANALYTICS.MART_PAYMENT_KPIS WHERE SUCCESS_RATE_PCT BETWEEN 0 AND 100) > 0,
        '✅ ALL CHECKS PASSED - proceed to Step 4',
        '❌ VALIDATION FAILED - ask Cortex Code to fix the issues shown above'
    ) AS FINAL_VERDICT;

-- =====================================================
-- STEP 3: CORTEX AI ENRICHMENT
-- =====================================================

USE SCHEMA ANALYTICS;

-- 3.1: Sentiment Analysis on Customer Feedback
CREATE OR REPLACE TABLE BARCLAYS_HOL.ANALYTICS.FEEDBACK_ENRICHED AS
SELECT
    f.FEEDBACK_ID,
    f.FEEDBACK_DATE,
    f.CUSTOMER_NAME,
    f.FEEDBACK_CHANNEL,
    f.FEEDBACK_TEXT,
    f.PAYMENT_TYPE,
    f.RATING,

    -- Sentiment score (-1 to +1)
    ROUND(SNOWFLAKE.CORTEX.SENTIMENT(f.FEEDBACK_TEXT), 3) AS SENTIMENT_SCORE,

    -- Classify sentiment
    CASE
        WHEN SNOWFLAKE.CORTEX.SENTIMENT(f.FEEDBACK_TEXT) > 0.3 THEN 'POSITIVE'
        WHEN SNOWFLAKE.CORTEX.SENTIMENT(f.FEEDBACK_TEXT) < -0.3 THEN 'NEGATIVE'
        ELSE 'NEUTRAL'
    END AS SENTIMENT_LABEL,

    -- Auto-classify the feedback topic
    SNOWFLAKE.CORTEX.CLASSIFY_TEXT(
        f.FEEDBACK_TEXT,
        ['Performance Issue', 'Service Quality', 'Technical Problem', 'Positive Experience', 'Feature Request']
    ):label::STRING AS TOPIC_CATEGORY,

    -- Confidence score
    SNOWFLAKE.CORTEX.CLASSIFY_TEXT(
        f.FEEDBACK_TEXT,
        ['Performance Issue', 'Service Quality', 'Technical Problem', 'Positive Experience', 'Feature Request']
    ):score::FLOAT AS CLASSIFICATION_CONFIDENCE

FROM RAW_DATA.CUSTOMER_FEEDBACK f;

-- Preview enriched results
SELECT
    FEEDBACK_TEXT,
    SENTIMENT_SCORE,
    SENTIMENT_LABEL,
    TOPIC_CATEGORY,
    ROUND(CLASSIFICATION_CONFIDENCE, 2) AS CONFIDENCE
FROM FEEDBACK_ENRICHED
LIMIT 10;

    a.ALERT_ID,

    a.ALERT_DESCRIPTION,

SQL 
-- 3.3: Sentiment Distribution Summary
SELECT
    SENTIMENT_LABEL,
    COUNT(*) AS FEEDBACK_COUNT,
    ROUND(AVG(SENTIMENT_SCORE), 3) AS AVG_SCORE,
    ROUND(COUNT(*)::FLOAT / (SELECT COUNT(*) FROM FEEDBACK_ENRICHED) * 100, 1) AS PERCENTAGE
FROM FEEDBACK_ENRICHED
GROUP BY SENTIMENT_LABEL
ORDER BY FEEDBACK_COUNT DESC;

-- 3.4: Sentiment by Payment Type
SELECT
    PAYMENT_TYPE,
    COUNT(*) AS TOTAL_FEEDBACK,
    ROUND(AVG(SENTIMENT_SCORE), 3) AS AVG_SENTIMENT,
    COUNT(CASE WHEN SENTIMENT_LABEL = 'NEGATIVE' THEN 1 END) AS NEGATIVE_COUNT,
    ROUND(COUNT(CASE WHEN SENTIMENT_LABEL = 'NEGATIVE' THEN 1 END)::FLOAT / COUNT(*) * 100, 1) AS NEGATIVE_PCT
FROM FEEDBACK_ENRICHED
GROUP BY PAYMENT_TYPE
ORDER BY AVG_SENTIMENT ASC;

4.4 — Dynamic Tables: Real-Time Operational Layer

Now add a continuously-refreshing operational layer on top of the AI-enriched data. Dynamic Tables refresh automatically when source data changes — no orchestration, no scheduling, no stored procedures.

💡
dbt vs Dynamic Tables

dbt builds your batch transformation layer (scheduled, versioned, tested). Dynamic Tables add a continuous operational layer that refreshes itself. They complement each other — use dbt for the governed data model and DTs for live operational views.

SQL 
-- =====================================================
-- 4.4: DYNAMIC TABLES - Real-Time Operational Layer
-- These refresh automatically when FEEDBACK_ENRICHED changes
-- =====================================================

USE SCHEMA BARCLAYS_HOL.ANALYTICS;

-- DT 1: Live Negative Sentiment Alert Feed
-- Surfaces negative feedback within the last 24 hours, refreshing every minute
CREATE OR REPLACE DYNAMIC TABLE DT_NEGATIVE_SENTIMENT_FEED
    TARGET_LAG = '1 minute'
    WAREHOUSE = BARCLAYS_WH
AS
SELECT
    FEEDBACK_ID,
    FEEDBACK_DATE,
    CUSTOMER_NAME,
    PAYMENT_TYPE,
    FEEDBACK_CHANNEL,
    FEEDBACK_TEXT,
    SENTIMENT_SCORE,
    TOPIC_CATEGORY,
    CLASSIFICATION_CONFIDENCE
FROM FEEDBACK_ENRICHED
WHERE SENTIMENT_LABEL = 'NEGATIVE'
  AND FEEDBACK_DATE >= DATEADD('hour', -24, CURRENT_TIMESTAMP())
ORDER BY FEEDBACK_DATE DESC;

-- Preview the live feed
SELECT * FROM DT_NEGATIVE_SENTIMENT_FEED LIMIT 10;
SQL 
-- DT 2: Operational Sentiment Summary (cascading - refreshes downstream of DT 1)
-- Aggregates sentiment metrics by payment type for operational dashboards
CREATE OR REPLACE DYNAMIC TABLE DT_SENTIMENT_OPS_SUMMARY
    TARGET_LAG = DOWNSTREAM
    WAREHOUSE = BARCLAYS_WH
AS
SELECT
    PAYMENT_TYPE,
    COUNT(*) AS TOTAL_FEEDBACK,
    COUNT(CASE WHEN SENTIMENT_LABEL = 'NEGATIVE' THEN 1 END) AS NEGATIVE_COUNT,
    COUNT(CASE WHEN SENTIMENT_LABEL = 'POSITIVE' THEN 1 END) AS POSITIVE_COUNT,
    ROUND(AVG(SENTIMENT_SCORE), 3) AS AVG_SENTIMENT,
    ROUND(COUNT(CASE WHEN SENTIMENT_LABEL = 'NEGATIVE' THEN 1 END)::FLOAT / COUNT(*) * 100, 1) AS NEGATIVE_PCT,
    MAX(FEEDBACK_DATE) AS LATEST_FEEDBACK
FROM FEEDBACK_ENRICHED
GROUP BY PAYMENT_TYPE;

-- View the operational summary
SELECT * FROM DT_SENTIMENT_OPS_SUMMARY ORDER BY NEGATIVE_PCT DESC;
SQL 
-- DT 3: Live SLA Breach Counter
-- Counts active SLA breaches from the dbt mart, refreshing every minute
CREATE OR REPLACE DYNAMIC TABLE DT_LIVE_BREACH_COUNT
    TARGET_LAG = '1 minute'
    WAREHOUSE = BARCLAYS_WH
AS
SELECT
    PAYMENT_TYPE,
    COUNT(*) AS BREACH_DAYS,
    MIN(PAYMENT_DATE) AS FIRST_BREACH,
    MAX(PAYMENT_DATE) AS LATEST_BREACH
FROM MART_SLA_COMPLIANCE
WHERE SLA_STATUS = 'BREACH'
  AND PAYMENT_DATE >= DATEADD('day', -7, CURRENT_DATE())
GROUP BY PAYMENT_TYPE;

-- View active breaches
SELECT * FROM DT_LIVE_BREACH_COUNT ORDER BY BREACH_DAYS DESC;

-- Monitor Dynamic Table health
SHOW DYNAMIC TABLES IN SCHEMA ANALYTICS;

-- Check refresh history
SELECT
    NAME,
    STATE,
    REFRESH_START_TIME,
    REFRESH_END_TIME,
    TIMEDIFF('second', REFRESH_START_TIME, REFRESH_END_TIME) AS DURATION_SECONDS
FROM TABLE(INFORMATION_SCHEMA.DYNAMIC_TABLE_REFRESH_HISTORY(
    NAME => 'ANALYTICS.DT_NEGATIVE_SENTIMENT_FEED'
))
ORDER BY REFRESH_START_TIME DESC
LIMIT 5;

SQL 
-- =====================================================
-- STEP 4: CORTEX AI ENRICHMENT
-- Companion file: sql/04_cortex_ai.sql
-- =====================================================

USE SCHEMA BARCLAYS_HOL.ANALYTICS;

-- 4.1: Sentiment Analysis on Customer Feedback
CREATE OR REPLACE TABLE FEEDBACK_ENRICHED AS
SELECT
    f.FEEDBACK_ID,
    f.FEEDBACK_DATE,
    f.CUSTOMER_NAME,
    f.FEEDBACK_CHANNEL,
    f.FEEDBACK_TEXT,
    f.PAYMENT_TYPE,
    f.RATING,

    -- Sentiment score (-1 to +1)
    ROUND(SNOWFLAKE.CORTEX.SENTIMENT(f.FEEDBACK_TEXT), 3) AS SENTIMENT_SCORE,

    CASE
        WHEN SNOWFLAKE.CORTEX.SENTIMENT(f.FEEDBACK_TEXT) > 0.3  THEN 'POSITIVE'
        WHEN SNOWFLAKE.CORTEX.SENTIMENT(f.FEEDBACK_TEXT) < -0.3 THEN 'NEGATIVE'
        ELSE 'NEUTRAL'
    END AS SENTIMENT_LABEL,

    -- Auto-classify the feedback topic
    SNOWFLAKE.CORTEX.CLASSIFY_TEXT(
        f.FEEDBACK_TEXT,
        ['Performance Issue', 'Service Quality', 'Technical Problem', 'Positive Experience', 'Feature Request']
    ):label::STRING AS TOPIC_CATEGORY,

    SNOWFLAKE.CORTEX.CLASSIFY_TEXT(
        f.FEEDBACK_TEXT,
        ['Performance Issue', 'Service Quality', 'Technical Problem', 'Positive Experience', 'Feature Request']
    ):score::FLOAT AS CLASSIFICATION_CONFIDENCE

FROM BARCLAYS_HOL.RAW_DATA.CUSTOMER_FEEDBACK f;

-- Preview
SELECT FEEDBACK_TEXT, SENTIMENT_SCORE, SENTIMENT_LABEL, TOPIC_CATEGORY
FROM FEEDBACK_ENRICHED LIMIT 10;
SQL 
-- 4.2: AI-generated recommended actions for open high-severity alerts
SELECT
    a.ALERT_ID,
    a.SEVERITY,
    a.ALERT_DESCRIPTION,
    a.PAYMENT_TYPE,
    SNOWFLAKE.CORTEX.COMPLETE(
        'mistral-large2',
        'You are a payments operations analyst at a major UK bank. ' ||
        'Given this alert: "' || a.ALERT_DESCRIPTION || '" ' ||
        'for payment type: ' || a.PAYMENT_TYPE || ' ' ||
        'with severity: ' || a.SEVERITY || '. ' ||
        'Provide a one-sentence recommended action.'
    ) AS AI_RECOMMENDED_ACTION
FROM BARCLAYS_HOL.RAW_DATA.OPERATIONAL_ALERTS a
WHERE a.STATUS = 'OPEN'
  AND a.SEVERITY IN ('HIGH', 'CRITICAL')
LIMIT 5;
SQL 
-- 4.3: Sentiment by payment type
SELECT
    PAYMENT_TYPE,
    COUNT(*) AS TOTAL_FEEDBACK,
    ROUND(AVG(SENTIMENT_SCORE), 3) AS AVG_SENTIMENT,
    COUNT(CASE WHEN SENTIMENT_LABEL = 'NEGATIVE' THEN 1 END) AS NEGATIVE_COUNT,
    ROUND(COUNT(CASE WHEN SENTIMENT_LABEL = 'NEGATIVE' THEN 1 END)::FLOAT / COUNT(*) * 100, 1) AS NEGATIVE_PCT
FROM FEEDBACK_ENRICHED
GROUP BY PAYMENT_TYPE
ORDER BY AVG_SENTIMENT ASC;
