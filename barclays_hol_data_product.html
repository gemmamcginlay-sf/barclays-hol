Environment Setup

~5 min

Create the database, schemas, and warehouse for the lab. We organise data into two schemas: RAW_DATA for source tables and ANALYTICS for dbt-transformed and AI-enriched objects.

1.1 — Open a SQL Worksheet

In Snowsight, click Projects → Worksheets → + SQL Worksheet. Copy and run the setup SQL below (or open sql/01_setup.sql from the workspace).

sql/01_setup.sql 
-- Create the lab database
CREATE OR REPLACE DATABASE BARCLAYS_HOL
    COMMENT = 'Barclays Payments Data Product - Hands-on Lab';

-- Create organised schemas
CREATE OR REPLACE SCHEMA BARCLAYS_HOL.RAW_DATA
    COMMENT = 'Raw payments and operations data';
CREATE OR REPLACE SCHEMA BARCLAYS_HOL.ANALYTICS
    COMMENT = 'dbt-transformed and AI-enriched views';

-- Create warehouse
CREATE OR REPLACE WAREHOUSE BARCLAYS_WH
    WITH WAREHOUSE_SIZE = 'SMALL'
    AUTO_SUSPEND = 60  AUTO_RESUME = TRUE
    INITIALLY_SUSPENDED = TRUE
    COMMENT = 'Warehouse for Barclays HOL';

USE WAREHOUSE BARCLAYS_WH;
USE DATABASE BARCLAYS_HOL;
USE SCHEMA RAW_DATA;

-- Verify Cortex AI is available
SELECT SNOWFLAKE.CORTEX.SENTIMENT('Payment processed successfully') AS cortex_test;

-- Note available compute pools (needed for Streamlit bonus step)
SHOW COMPUTE POOLS;
✅
Verification

You should see a sentiment score (positive number close to 1.0) confirming Cortex AI is available in your region.

Build the dbt Layer + Accelerate with Cortex Code

~25 min

This step is split into two parts. In 3a, we walk through the pre-built dbt project (4 staging views + 2 mart tables). In 3b, we use Cortex Code to build 2 additional mart models — demonstrating AI-accelerated development.

3a — Walkthrough: The Pre-Built dbt Project (15 min)

Open the dbt/ folder in your workspace. The project is already scaffolded:

Project Structure 
dbt/
  dbt_project.yml
  profiles.yml
  macros/
    generate_schema_name.sql    -- ensures models deploy to ANALYTICS (not ANALYTICS_ANALYTICS)
  models/
    staging/
      schema.yml                -- 9 sources + 4 staging model tests
      stg_payments.sql          -- cleans PAYMENTS, adds IS_SUCCESSFUL/IS_FAILED flags
      stg_feedback.sql          -- cleans CUSTOMER_FEEDBACK, adds SATISFACTION_TIER
      stg_customers.sql         -- joins CUSTOMERS + RELATIONSHIP_MANAGERS (denormalises RM)
      stg_accounts.sql          -- joins ACCOUNTS + CUSTOMERS (denormalises sector)
    marts/
      schema.yml                -- mart model definitions + CoCo-built models
      mart_payment_kpis.sql     -- daily KPIs: payments -> accounts -> customers
      mart_sla_compliance.sql   -- daily SLA compliance per scheme
📚
Key Design Decisions

Staging views clean, type-cast, and add derived flags. They reference raw tables via {{ source() }}.
Mart tables are denormalised aggregations. mart_payment_kpis joins through the full entity chain (payments → accounts → customers) to get customer sector and RM dimensions at the daily grain.
Custom macro: generate_schema_name.sql ensures the custom schema ANALYTICS is used as-is (not prefixed with the default schema).

Explore each file — the presenter will walk through the key patterns. Then run:

Terminal (Cortex Code) 
dbt run --project-dir dbt
dbt test --project-dir dbt

Then validate with sql/03_validate_dbt.sql (section 3a). You should see all 6 tables pass.

4

Cortex AI Enrichment + Dynamic Tables

~20 min

This step runs as a Snowflake Notebook (sql/04_cortex_ai.ipynb) with SQL, Python, and Markdown cells. We'll enrich customer feedback with three Cortex AI functions, visualise the results with Python, generate LLM-powered alert recommendations, and create auto-refreshing Dynamic Tables.

4.1 — Open the Notebook

In your workspace, open sql/04_cortex_ai.ipynb. It will launch in Snowflake Notebooks with a SQL/Python kernel.

4.2 — AI Enrichment: FEEDBACK_ENRICHED

The first section creates a FEEDBACK_ENRICHED table using a CTE that calls each AI function exactly once per row:

  • SNOWFLAKE.CORTEX.SENTIMENT() — scores feedback text from -1.0 (negative) to +1.0 (positive)
  • SNOWFLAKE.CORTEX.CLASSIFY_TEXT() — classifies feedback into topics (Service Quality, Technical Issue, etc.)
  • Derives SENTIMENT_LABEL (POSITIVE/NEUTRAL/NEGATIVE) and SATISFACTION_TIER from the scores
⚡
Performance Optimisation

The CTE pattern ensures each AI function is called once per row, not multiple times. This halves the processing time and token cost vs. calling functions inline in the SELECT.

4.3 — Python Visualisation

Python cells generate matplotlib charts showing the sentiment score distribution and topic category breakdown — giving a visual sanity check on the AI enrichment quality.

4.4 — LLM Recommendations

The notebook uses SNOWFLAKE.CORTEX.COMPLETE('llama3.1-8b', ...) to generate operational recommendations for the 5 most critical alerts. This demonstrates how an LLM can synthesise context from payment data and alert details into actionable guidance.

4.5 — Dynamic Tables

Three Dynamic Tables create an auto-refreshing operational layer:

Dynamic Table Purpose Lag
DT_PAYMENT_SUMMARYHourly payment volume, success rate, and processing times by schemeDOWNSTREAM
DT_SENTIMENT_TRACKERRolling sentiment aggregation with alert triggers when score drops below -0.2DOWNSTREAM
DT_LIVE_SLA_BREACHESLive count of SLA breach volume per scheme in the last 24 hours1 minute
📚
Dynamic Table Concepts

TARGET_LAG = DOWNSTREAM means "refresh when a downstream consumer needs me" — cost-efficient for tables consumed by dashboards or other DTs. TARGET_LAG = '1 minute' means "refresh at most every minute" — used for the SLA breach counter which needs near-real-time visibility.

Run all cells in the notebook top to bottom. The AI enrichment step takes ~60 seconds for 2,000 feedback rows.

✅
Verification

Check that FEEDBACK_ENRICHED has ~2,000 rows with SENTIMENT_SCORE and TOPIC_CATEGORY populated. The Dynamic Tables should show as ACTIVE when you run SHOW DYNAMIC TABLES;

Semantic View + Cortex Agent

~15 min

Create a production-quality Semantic View via DDL that captures relationships, metrics, verified queries, and AI instructions. Then deploy a Cortex Agent that uses this Semantic View to answer natural language questions in CoWork.

5.1 — Create the Semantic View

Open sql/05_intelligence.sql and run section 5.1. This creates SV_PAYMENTS with:

  • 3 logical tables: payments (MART_PAYMENT_KPIS), sla (MART_SLA_COMPLIANCE), feedback (FEEDBACK_ENRICHED)
  • 1 relationship: payments ↔ sla on (PAYMENT_DAY, PAYMENT_TYPE)
  • 16 facts: volumes, rates, processing times, SLA gaps, sentiment scores
  • 12 dimensions: payment type, channel, region, sector, RM, SLA status, sentiment label, topic
  • 7 metrics: weighted success/failure rates, breach count, average sentiment, etc.
  • 8 verified queries: common questions with pre-validated SQL (monthly volume, success by scheme, SLA breaches, top RMs, etc.)
  • AI instructions: AI_SQL_GENERATION teaches the model about UK payment schemes and correct aggregation patterns; AI_QUESTION_CATEGORIZATION routes questions to the right logical table
💡
Why DDL for Semantic Views?

Writing Semantic Views as SQL DDL (rather than using the UI builder) makes them version-controllable, reviewable, and deployable through CI/CD — critical for production data products. The verified queries teach the AI how to answer domain-specific questions correctly.

5.2 — Create the Cortex Agent

Run section 5.2 of the same script. This creates PAYMENTS_ASSISTANT — a Cortex Agent that:

  • Uses cortex_analyst_text_to_sql to query the Semantic View
  • Has data_to_chart for automatic visualisations
  • Includes response instructions (formatting, weighted success rates) and orchestration instructions (routing to the right logical table)
  • Lists sample questions for the CoWork onboarding experience

5.3 — Test in CoWork

Navigate to CoWork (left navigation bar). The Payments Assistant should appear as an available agent. Try these questions:

In a real data product, discoverability is everything. Comments appear in Snowsight search results, Cortex Code suggestions, and the data catalog. They help other teams understand your data without needing to read your code.
